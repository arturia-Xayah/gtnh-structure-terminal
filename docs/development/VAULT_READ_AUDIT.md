## 明确存在的性能边界

1. 身份键缓存每通道只限制 4096 条，没有累计字节预算。缓存值包含完整 canonical key 和 payload；平均每条合计 200 KiB 时，4096 条约 800 MiB，不含 Java 对象及共享标签引用。物品与流体适配器分别缓存，不能将条数上限称为整机内存上限。原型缓存按所列库存类型保存，也没有独立字节预算。
2. 顺序轮询 4097 种身份，超过 4096 的 LRU 后可持续失效；除了重新编码，还有缓存管理成本。随机 NBT、UUID 或时间戳造成不断出现的新身份，也会污染缓存。不能宣称查询普遍更快；此前整包阶段压力数据已保留回退。
3. 数量变化后立即获取完整视图仍重建 long 数组。类型变化还会重建 Resource 数组，以及适配器的完整原型引用映射/数组，即使只增删一个类型。单次完整返回仍是 O(N)。变更后反复立即枚举可形成 O(变更次数 × 类型数) 的工作量和大量临时分配。
4. 首次读取、重新挂载和大量机器同时加载都需要建缓存。不能仅按热枚举耗时预算加载峰值。

补充隔离实验使用实际当前核心 class，1000/10000/100000 类型，每格 100 次预热、200 次测量。每次变更成对写日志后读取快照，结束核对类型数和数量守恒。未启动客户端。这里只测核心视图，未计 AE 列表和适配器原型映射，所以不是整包 MSPT：

| 类型数 | 数量变更后每次分配 | 类型出现/消失后每次分配 |
|---|---:|---:|
| 1000 | 约 10 KB | 约 14 KB |
| 10000 | 约 82 KB | 约 122 KB |
| 100000 | 约 802 KB | 约 1202 KB |

100000 类型的一次类型变化重建，仅这里已分配约 1.2 MB。若每秒发生 1000 次这样的重建，分配速率就约 1.2 GB/s；这是假设频率的算术估计，不是本次服务器实测吞吐。未变化时复用同一个不可变快照。单 JVM 时间受预热、GC 和日志 IO 影响，不据此给出稳定延迟保证。

## 正确性与线程边界

已验证的行为：模拟不变、物品/流体分别失效、数量饱和可见量、删除后重新插入、旧快照不随以后写入改变、通过原生 setter 更换标签后修复缓存原型。

尚未验收的兼容性边界：快速身份键及原型修复使用共享标签的对象身份。实际 1095 开发 JAR 中 AESharedNBT 继承可变 NBTTagCompound，没有覆写所有修改方法以强制只读。如果第三方绕过共享标签按不可变处理的约定，原地修改同一对象，标签引用不变，键缓存可能继续命中旧编码，原型修复也不能只凭引用发现。这是静态推导的兼容性风险，尚未作整包复现；同时也会破坏原生 AE 的共享标签假设，不能称普通 AE 操作必然触发。

并发与回调风险：完整枚举持适配器锁调用结构检查和 out.addStorage；结构检查可能重新绑定/解绑，而解绑会清理两个适配器。代码还在可用性检查之后和异常处理中重复解引用 access.bound。在并发解绑或自定义列表回调重入时，存在绑定变空、缓存数组被清空及锁顺序风险。不可变数量快照不等于整个接口可任意跨线程调用。正常主线程路径已通过后台检查；任意后台线程与重入解绑尚未压力验收。世界状态应在主线程访问，后台只消费不可变数据；建议缩小锁范围、保存本次仓库/数组局部引用，并避免在缓存锁内调用外部回调。

建议先加入总字节预算、超大 NBT 准入限制、抗顺序扫描污染，以及类型增删的增量原型维护。字节预算应涵盖每机两通道与全服务器总量，避免几十台各自达到上限。预算不足时允许少缓存/重新解码，不能少返回类型或返回不完整列表。

## 多聚合器的优化顺序

1. 共享不可变资源定义/编码结果，减少不同机器存相同类型时的重复内存和解析。实例数量、容量、文件及归属独立；可变 AE 栈副本隔离。共享缓存仍需要预算和世界生命周期清理。
2. 在同一个实际 AE grid 内维护增量索引：资源 → BigInteger 总量、持有该资源的仓库及各自数量/优先级/挂载代次。查询聚合器部分不再逐台询问，取出只定位有关持有者。索引变化由实际提交的数量变化驱动，模拟不更新；从精确总量派生饱和 long，不能对已经饱和的总量直接减去增量。
3. 接入 AE 查询/枚举入口，一次返回去重的聚合器贡献；其他 AE 存储继续原生处理。若原生仍逐台调用，而每台返回共享总量，会重复计数。仅创建共享 Map 不会自动消除原生循环。
4. 保留全部存取优先级、频道/电力、过滤、安全、网络来源与 Reshuffle 语义。一个优先级 100 的聚合器、原生优先级 50 的元件、另一个优先级 0 的聚合器，不能合成一个统一优先级端点，否则改变存入顺序。只读总量可合并；真实 IO 必须保留实际全局次序，或按优先级分组后原位接入。
5. 不同 grid 的库存不共享可访问性；外部子网的可见过滤与原生去重仍由对应视图处理。输出总线模式未挂载的私有库存不能计入网络存储。网络分裂/合并、卸载、断电、结构失效与复制 UUID 的挂载状态都要准确失效。
6. 合并/分裂可触发全量重建，需预算、代次校验和重建期间的原生回退。完整新索引可用后再切换，不能把部分索引当完整库存公开。不能通过每次查询重新检查所有机器来维护所谓 O(1)，也不能无条件缓存结构状态而允许已拆机器继续供货。

复杂度取决于资源键长度、BigInteger 位数及存储数量：聚合器精确总量索引的 Map 查找平均 O(1)；实际取出至少访问有关机器；完整枚举至少 O(U)（不同资源类型数）。其他 AE 存储、模糊匹配和过滤子网路径仍可能需要额外遍历。
