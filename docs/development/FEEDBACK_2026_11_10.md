# 2026-11-10 修正与验证

本地未发布测试包，内部版本仍为 `0.3.4-alpha`，适配 GTNH 2.9.0。下载与校验信息见 [manifest](../../verification/feedback-2026-11-10/manifest.json)。没有修改已有 GitHub Release。

## 实现

- 聚合器物品模型改用新白蓝紫底纹，修正物品模型的主机正面朝向。成型时使用客户端同步的结构范围查询所属主机，避免分块渲染快照缺少邻接 TileEntity 时回退旧材质。主机、ME 端口和普通 GT 仓室保留功能标识。
- 在原连续底纹上用图像生成工具调整白色基底、青蓝与紫色线路，缩放至 512×512。仍使用一个整面图集及共享的 3×3 UV 边界；四周近白色、不透明。实际资源为 `assets/aestoragevault/textures/blocks/formed_shell_smooth.png`。
- 高级终端深色偏好保存在 `gtnh-modernization-client.cfg` 的 `client.terminalDarkMode`，默认开启；浅色模式也降低亮度。物品绘制设置正常 GUI 照明和光照贴图，并恢复此前状态。背包键关闭界面。
- 玻璃一级菜单只包含原生 GlassTier 的功能等级；二级菜单保留同级变体与 Auto。Auto 优先已有玻璃，再选背包和 AE 中同等级材料，不消耗扫描材料。
- 仓室拆除不再使用额外完整 NBT 包装。确认权限及预检后调用原生 `getDrops` 和 `breakBlock`；原生销毁钩子决定哪些内容能够掉落，流体不额外保存。同步产生的物品掉落导入现有回收通道。AE 拒收余料保留在终端重试；主机仍保留，外来障碍物、保护区及禁止破坏的方块不会强拆。
- VaultStore 增量维护每频道用量和类型数，网络工具更新无需枚举全库。物品、流体页的容量均为各自已用量加共享空闲容量，不能相加当成独立容量；原生网络工具使用近似数值，底层库存不损失大整数精度。
- 多配方报告只显示主产物与配方数，循环只显示主产物链；彩色下划线链接解析实际接口／TileEntity 提供方。链接绑定报告接收玩家、有效 10 分钟，每人最多保留 256 条，每页最多 32 个位置。当前维度已加载位置高亮 30 秒，其他维度报告名称与坐标。不加载区块或传送玩家。未知第三方提供器若不暴露位置，会报告无法定位；移动样板后应重新计算。

## 验证结果

- Gradle `check assemble`、Checkstyle、Spotless 通过；163 项单元测试通过。
- GTNH 2.9.0 隔离后台服务器、Java 25：185 项 AE 检查、81 项聚合器检查、7 项新进程重启检查通过，共 273 项。
- 新增覆盖：物品／流体频道网络工具统计；原生空仓、含物品仓、含流体仓拆除及 AE 回收；无重复地面掉落；保留主机及仓室开关；各玻璃等级唯一分组、原生材料谓词、Auto 按库存选择；紧凑报告的样式、命令点击和实际接口坐标、跨维度坐标和失效链接。
- 跨维度报告测试临时让同一个真实接口引用另一服务端维度，生成报告后立即恢复。它验证定位消息的维度信息，不代表搭建并验收了一条跨维度量子网络。
- 正式包包含 233 个 Java 8 字节码类，无测试夹具。与执行过的夹具逐类比较，运行指令一致；显式导入整理仅改变两个 PatternLocations 类的调试行号。
