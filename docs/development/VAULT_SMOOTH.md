# 0.2.2 仓库整面材质与独占部件

## 结构规则

`VaultGeometry` 使用主机 metadata 的六方向法向量确定空心中心，主机因此必须在面中央并朝外。结构体为中心周围 26 个格子：主机、总线、接口各一，其余 23 个为原生 LuV 外壳。

`VaultStructure.inspect` 只检查实际材料与数量。`inspectExclusive` 额外检查总线与接口周围已加载的候选主机：另一完整结构使用同一功能部件时，两者均拒绝成型。判定不依赖谁先运行，且在每次 AE 访问时复查，避免已挂载库存绕过冲突。形状失效的旧接口绑定可释放，无需拆掉接口重放。

`NativeBusOwnershipMixin` 在原生 `MTEMultiBlockBase.checkStructure` 成功返回时记录输入总线。弱引用索引只认仍有效、成型且列表仍含该总线的原生机器；仓库不接管其总线。索引不是持久化数据，世界重新加载时由原机结构检测重新登记。第三方机器若完全绕过这一 GT 原生结构检查入口，不在该登记保证范围内。

## 材质

所有形成结构的外壳、主机、接口和总线共享一张 192×192 整面纹理，按每面坐标选用九张 64×64 切片。`VaultGeometry.tile` 定义六个面的 UV 方向。

- 原生 LuV 外壳通过客户端 `GTRendererCasing.renderWorldBlock` 注入切换显示；只有有效仓库成员受影响。
- 自定义主机和接口使用同一套整面材质渲染，并叠加原功能面板。
- 总线返回对应切片的 `ITexture`，仍使用原生输入端口覆盖层。
- 不替换世界方块，不写总线材质、等级或染色 NBT，不改配方或库存文件。形状失效时回到原显示路径。

客户端贴图字段在图集注册阶段初始化；不能在公共静态初始化器中赋值给被 `@SideOnly(CLIENT)` 删除的字段。单元测试以字节码防止此问题回归。

原始图、最终整面图、切片路径、内置 image_gen 工具与完整提示词见 [生成记录](../assets/vault/formed-shell-generation.json)。网页预览直接使用这九张运行时切片。未启动游戏客户端，不将浏览器近似光照视作实际客户端 OpenGL 验收。

## 验证

六个朝向分别将总线和接口放遍主机外的 25 个外壳位置，共 300 种真实服务器布局；另检查非面中央主机、共用总线/接口的双向拒绝、解除冲突恢复和原生 GT 总线登记/释放。原生登记测试使用实际 GT 主机与总线对象，主动构造其登记状态，并非另一台完整 GT 机器的实物成型测试。当前整合回归见 [验证报告](VALIDATION.md)。
